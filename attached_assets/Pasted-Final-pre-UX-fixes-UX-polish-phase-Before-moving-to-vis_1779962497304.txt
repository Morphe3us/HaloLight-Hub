PHASE 1 — FINAL FUNCTIONAL FIXES BEFORE UX POLISH
=================================================

1. Contract equipment selector

Current issue:
In the New Contract form, the equipment selector must clearly display the registered equipment.

Fix:

* Show equipment product/model name
* Serial number if available
* Status if available

Example:
[ ] HaloLight Box — Canon 2000D — SN: HL-BOX-001

If no equipment exists:
Show:
“No equipment registered yet. Add equipment in Hardware.”

2. Equipment description in contract

Current issue:
Contract output must never show:
undefined
null
empty object
empty array

Fix:

* If equipment is selected, show selected equipment details.
* If manual equipment description exists, show it too.
* If both exist, show selected equipment first, then manual notes.
* If nothing exists, show localized fallback:
  FR: Matériel à préciser
  EN: Equipment to be specified

3. Auto-fill equipment description

When equipment is selected:

* automatically populate equipment description
* include product/model/serial number
* allow user to manually edit/add notes after selection

4. Contract number

Current issue:
Document header shows the real number, but body previously showed:
Contrat N° : À préciser

Fix:

* inject the real generated contract number into {{contract_number}}
* replace after final contract number generation if needed
* never use fallback for contract_number when contract.number exists

Expected:
Contrat N° : CON-2026-XXXX

5. Company logo on documents

Add company logo support in Settings/Profile:

* upload or save logo URL
* preview logo
* remove/replace logo

Use logo on:

* quotes
* contracts
* invoices

Important logo fallback rule:
If user/company uploaded a logo, display it.
If no logo is uploaded, show no logo.
Do NOT use HaloLight Hub logo as fallback on customer-facing documents.

The document belongs to the rental company, not HaloLight.

6. Provider signature

If provider signature is saved in Settings:

* show it in provider signature section
* contract can be sent already signed by the rental company

If missing:

* keep blank signature line.

7. Placeholder email issue

Current issue:
Generated documents can still show placeholder emails like:
[user_xxxx@placeholder.com](mailto:user_xxxx@placeholder.com)

This is not acceptable on client-facing documents.

Fix:

* Sync real email from Clerk/user profile wherever possible.
* If real email is missing, show a clear editable field in Settings/Profile.
* Do not display placeholder email on quotes/contracts/invoices.
* If no valid email is available, show localized fallback:
  FR: E-mail non renseigné
  EN: Email not provided

9. Options consistency

Current issue:
The contract can show:
Options supplémentaires : Aucune option supplémentaire

while pricing shows:
Options supplémentaires : 120,00 €

This is incoherent.

Fix:

* If options price > 0 and options description is empty, show localized fallback:
  FR: Options supplémentaires incluses
  EN: Additional options included
* If options description exists, show it.
* If options price = 0 and no options description, hide the options line.
* Never show “Aucune option supplémentaire” when an options amount exists.

10. Pricing / optional lines

Keep:

* correct currency formatting
* hide zero discount
* hide zero optional fees when irrelevant
* no duplicated currency code
* no raw {{variables}}

Rules:

* If discount = 0, hide discount line.
* If delivery fees = 0 and delivery is not selected, hide delivery fees.
* If options price = 0 and no options, hide options price.
* If tax = 0, hide tax line if applicable.
* Total must remain visible.

11. Contract text quality

User-filled free text can contain typos, but the system should not make the contract look unprofessional.

Add optional improvement:

* Add a “Improve wording” / “Clean text” button for long free-text sections:

  * equipment notes
  * deposit conditions
  * cancellation terms
  * payment terms
* It should not change legal meaning.
* It should only fix spelling, grammar and clarity.
* Keep this optional, not automatic.

12. Document design cleanup

Current output is functional but still too raw / AI-generated.

Improve print/PDF layout for:

* contracts
* quotes
* invoices

Design goal:
Professional, clean, client-facing business document.

Requirements:

* clean header with company logo if available
* no logo if no company logo uploaded
* document number clearly visible
* provider/client blocks in a clean layout
* event details in a clean section
* pricing table cleaner
* signature block cleaner
* better spacing
* no heavy “══════” separators
* use subtle borders/dividers
* printer/PDF friendly
* no overdesign
* make it look ready to send to a real client

13. Browser print artifacts

Current PDFs can show browser artifacts like:
about:blank
browser date/time
page title

If possible:

* improve print CSS/title handling to reduce these artifacts
* set document title properly before print
* ensure the exported PDF title is the contract number

If browser limitations prevent full removal, document the limitation clearly.

14. Final verification for contracts

Create a new contract after template reset if needed.

Verify:

* equipment names visible in selector
* selected equipment appears in contract
* no undefined
* contract number appears in header and body
* logo appears if uploaded
* no logo appears if not uploaded
* placeholder email never appears
* document header language is correct
* options line is coherent with options pricing
* provider signature appears if saved

* print/export is professional
